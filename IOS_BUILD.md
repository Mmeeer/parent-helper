# iOS Build & Release Guide

Instructions for shipping Prime Kids to the App Store. Two very different paths:

- **Parent app** — Expo / React Native, mostly checklist work, ~1 week
- **Child app** — Must be rebuilt as native iOS (Family Controls framework), ~10–15 weeks

This document covers both.

## Shared prerequisites

These apply to both apps. Get these in place before any code is written.

### 1. Apple Developer Program enrollment

- **Cost**: $99 USD / year
- **URL**: https://developer.apple.com/programs/
- **Type**: Individual or Organization. Use Organization if you have a registered business — gives you a company-branded developer name on the store, and required for Family Controls entitlement.
- **Verification**: For Organization accounts, Apple requires a D-U-N-S number (free, ~5 business days from https://dnb.com).
- **Status check**: After enrollment, log in to https://appstoreconnect.apple.com — you should see "Apps", "Users and Access", etc.

### 2. App Store Connect setup

For **each app** (parent + child):

1. Log in to https://appstoreconnect.apple.com
2. **My Apps → +** → **New App**
3. Platform: **iOS**
4. Name: `Prime Kids: Parent Helper` (parent) or `Prime Kids` (child)
5. Primary language: `English (U.S.)` (you can add Mongolian later)
6. Bundle ID: pick from the dropdown — must match your `app.json` / Xcode project
   - Parent: `com.parenthelper.parent`
   - Child: `com.parenthelper.child`
7. SKU: any unique string (e.g., `parenthelper-parent-001`)
8. User Access: Full Access

### 3. APNs Authentication Key (for push notifications)

Both apps will need to receive push notifications on iOS.

1. https://developer.apple.com/account/resources/authkeys/list
2. **Keys** → **+** → **Apple Push Notifications service (APNs)**
3. Name: `Prime Kids APNs Key`
4. Download the `.p8` file — **you can only download it once, store securely**
5. Note the Key ID and Team ID shown after creation
6. Upload `.p8` to Firebase Console → Project Settings → Cloud Messaging → APNs Authentication Key

The same APNs key works for both parent and child apps (one key per developer account).

## Parent app — iOS build

The parent app is React Native via Expo, already configured for iOS in `app.json`. This is the straightforward path.

### Step 1 — Update `parent-app/app.json` for iOS

Open `parent-app/app.json` and verify / add the iOS-specific keys:

```json
{
  "expo": {
    "ios": {
      "bundleIdentifier": "com.parenthelper.parent",
      "supportsTablet": true,
      "googleServicesFile": "./GoogleService-Info.plist",
      "buildNumber": "1",
      "infoPlist": {
        "NSLocationWhenInUseUsageDescription": "Show your child's location on the map.",
        "NSLocationAlwaysAndWhenInUseUsageDescription": "Receive your child's live location updates even when the Prime Kids app is in the background.",
        "NSCameraUsageDescription": "Scan the pairing QR code from your child's device.",
        "NSPhotoLibraryUsageDescription": "Pick a profile photo for your child.",
        "ITSAppUsesNonExemptEncryption": false
      }
    }
  }
}
```

Apple **requires** these usage description strings — they appear in the system permission dialogs. Without them, Apple's review will reject the app.

**Translations**: For Mongolian, create `parent-app/ios/InfoPlist.strings` per locale after `prebuild`. EAS handles this if you add a `lang` directory; otherwise English shows to all users (acceptable for v1).

### Step 2 — Generate iOS native project locally (one-time, optional)

If you want to inspect the iOS code (mostly autogenerated), run on a Mac:

```bash
cd parent-app
npx expo prebuild --platform ios --clean
```

This generates `parent-app/ios/`. You don't need to commit it — EAS regenerates it during cloud build.

### Step 3 — Build via EAS

EAS Build runs on Apple Silicon Macs in Anthropic's, sorry, in Expo's cloud — you don't need your own Mac for this.

```bash
cd parent-app
npx eas-cli build --platform ios --profile production
```

First-time prompts:
- **Apple ID** — your Apple Developer account email
- **App-specific password** — generate at https://appleid.apple.com/account/manage → "App-Specific Passwords"
- **Apple Team** — select your team (Individual or Organization)
- **Distribution certificate** — let EAS generate one (recommended) or upload your own
- **Provisioning profile** — let EAS generate

EAS stores these credentials securely; subsequent builds don't re-prompt. Build takes ~20–35 min in the cloud. Output is a signed `.ipa` file.

### Step 4 — Submit via EAS

```bash
npx eas-cli submit --platform ios --profile production
```

This uploads the `.ipa` to App Store Connect. Within a few minutes, you'll see it appear under your app's **TestFlight → Builds** tab.

### Step 5 — App Store Connect listing

Path: https://appstoreconnect.apple.com → your app → **App Information** + **Pricing and Availability** + **1.0 Prepare for Submission**.

Required fields:
- **Privacy Policy URL**: same one as Play Store (see memory)
- **Description**: ~4000 chars, marketing-friendly
- **Keywords**: 100 chars, comma-separated
- **Support URL** + **Marketing URL**
- **Category**: Primary `Lifestyle`, Secondary `Utilities`
- **Screenshots** (required sizes):
  - 6.7" (iPhone 15 Pro Max): 1290 × 2796
  - 6.5" (iPhone 11 Pro Max): 1242 × 2688
  - 5.5" (iPhone 8 Plus): 1242 × 2208
  - iPad 12.9": 2048 × 2732 (only if `supportsTablet: true`)
- **App Privacy** (questionnaire) — see below

### Step 6 — App Privacy questionnaire (the iOS equivalent of Google's Data Safety)

For each data type the parent app collects, declare:
- Collected? (Yes/No)
- Linked to user identity? (Yes/No)
- Used for tracking? (No — important!)
- Purposes: App Functionality only

For Prime Kids Parent app:
| Data type | Collected? | Linked? | Tracking? | Purpose |
|---|---|---|---|---|
| Email address | Yes | Yes | No | Account |
| Name | Yes | Yes | No | Account |
| Precise location (child) | Yes | Yes | No | App Functionality |
| App activity (child) | Yes | Yes | No | App Functionality |
| Crash data | Yes | No | No | Diagnostics |
| Device ID | Yes | Yes | No | App Functionality |

**Never mark "Used for tracking"** — that would flag App Tracking Transparency requirements you don't currently meet.

### Step 7 — Submit for review

After the build is uploaded and listing is complete:

1. App Store Connect → your app → **1.0 Prepare for Submission** tab
2. Scroll to **Build** section → "+ Add Build" → pick the build that's appeared from EAS
3. Fill in all required listing fields (will be marked red until complete)
4. **Submit for Review** button at top right

**Review timeline**: typically 24–72 hours. Apple is stricter than Google for first-time apps. Common rejection reasons covered in the [checklist below](#app-store-review-checklist-both-apps).

## Child app — native iOS build (from scratch)

The Android child app is built on Android-specific APIs (UsageStats, QUERY_ALL_PACKAGES, VpnService, Device Admin, SYSTEM_ALERT_WINDOW) that have no direct iOS equivalents. iOS requires using Apple's **Family Controls framework**, which is a fundamentally different architecture.

This section is a roadmap, not a copy-paste tutorial. iOS native development requires a Mac + Xcode and Swift familiarity.

### Step 1 — File the Family Controls Distribution entitlement application

**Do this BEFORE writing any code.** Apple's entitlement application takes 1–4 weeks. You cannot ship without it.

URL: https://developer.apple.com/contact/request/family-controls-distribution/

Application narrative (draft to adapt):

> Prime Kids is a parental control / family safety app. Parents install the parent app on their own device and pair it with a child app on the child's device. The child app uses Family Controls to:
>
> - Apply parent-configured app usage limits via DeviceActivity schedules and ManagedSettings shielding
> - Report the child's device location to the paired parent's account for safety
> - Present a parent-managed app block list using ApplicationToken and ShieldConfiguration
>
> Our Android version is already shipped on Google Play (com.parenthelper.child). Pairing is one-to-one, scoped to a single parent–child relationship, with explicit consent from the parent at setup. No data is shared with third parties or used for advertising.
>
> Use case: parents who want a unified family-safety solution across both Android and iOS in households with mixed devices.

Supporting docs to attach:
- Link to Google Play listing (once live)
- Privacy policy URL
- Screenshots of the existing Android parent + child apps

### Step 2 — Mac + Xcode setup

iOS native development requires:
- **Mac** with macOS 14 (Sonoma) or later
- **Xcode 15+** from the Mac App Store
- **iPhone with iOS 16+** for testing (Family Controls only works on real devices, not simulator)
- Apple Developer account signed in to Xcode (Settings → Accounts → +)

If you don't have a Mac:
- **Cloud Mac rental**: MacStadium ($79–$149/mo), MacInCloud ($30+/mo)
- **Mac mini purchase**: $599 — pays for itself within 6 months vs cloud rental

### Step 3 — Create the Xcode project

1. Xcode → File → New → Project → iOS → App
2. Product Name: `PrimeKidsChild`
3. Team: your Apple Developer team
4. Organization Identifier: `com.parenthelper`
5. Bundle Identifier: auto-fills to `com.parenthelper.PrimeKidsChild` — change to `com.parenthelper.child`
6. Interface: SwiftUI
7. Language: Swift
8. Storage: None (no Core Data yet)
9. Include Tests: Yes

### Step 4 — Add required capabilities and extensions

In Xcode, select the project → main app target → **Signing & Capabilities**:

- **+ Capability → Family Controls** (requires entitlement approval from Step 1)
- **+ Capability → App Groups** → add `group.com.parenthelper.child` (lets the main app share data with extensions)
- **+ Capability → Background Modes** → check `Location updates`
- **+ Capability → Push Notifications**

Then add three app extensions (File → New → Target → "Device Activity Monitor Extension" / "Managed Settings Configuration Extension" / "Shield Configuration Extension"):

| Extension | Purpose |
|---|---|
| `DeviceActivityMonitor` | Receives callbacks when DeviceActivity schedules fire (e.g., child exceeded daily limit) |
| `ManagedSettingsConfiguration` | Applies restrictions (shielding apps) when triggered |
| `ShieldConfiguration` | Customizes the "blocked" overlay shown by iOS when a restricted app launches |

Each extension needs to be added to the same App Group.

### Step 6 — Implementation roadmap (weekly)

| Week | Goal |
|---|---|
| 1 | Project scaffold, App Group, entitlements (after approval) |
| 2 | Pairing flow — UI + ApiClient POST to `/devices/complete-pairing` (reuse Android backend) |
| 3 | Location reporting — CoreLocation with `.authorizedAlways`, periodic heartbeat |
| 4 | Family Controls auth request — `AuthorizationCenter.shared.requestAuthorization(for: .child)` |
| 5 | App selection on parent side — backend serializes ApplicationToken blobs |
| 6 | DeviceActivity schedules — daily limits, "school hours" windows |
| 7 | ManagedSettings application — shield apps when limits exceeded |
| 8 | Shield UI — customize the blocked-app overlay via ShieldConfiguration |
| 9 | Localization (Mongolian strings) + accessibility audit |
| 10 | Real-device testing — pair with the parent app, validate end-to-end |
| 11 | App Store Connect listing + privacy questionnaire |
| 12 | Submit for review |

### Step 7 — Backend changes for iOS support

Most of the backend already handles iOS conceptually (`platform: "android" | "ios"`). What needs to be added:

1. **APNs push routing** — same Firebase Admin SDK can send to APNs; ensure the device's `deviceToken` field stores APNs tokens for iOS devices
2. **ApplicationToken storage** — iOS apps are identified by opaque base64 tokens, not bundle IDs. Add a column to the existing block list table to store iOS-shape tokens alongside Android package names. Recommend a polymorphic field like:
   ```javascript
   {
     "platform": "ios",
     "token": "<base64-blob>",
     "categoryTokens": [...]  // optional
   }
   ```
3. **Device pairing endpoint** — already accepts `platform: "ios"`. No change needed.

The frontend (Parent app) needs to render the block list differently for iOS children — instead of a list of installed apps (which iOS doesn't allow enumerating), the parent uses iOS's `FamilyActivityPicker` UI which returns opaque tokens. This is a parent-side iOS app feature.

### Step 8 — App Store Connect for child app

Same flow as the parent app:
- Listing with description, screenshots, keywords
- Privacy questionnaire (more sensitive data than parent app — location, app activity)
- Build uploaded via Xcode → Product → Archive → Distribute App → App Store Connect

**Critical for child app**: in the privacy questionnaire, declare data collection with `Linked to user: Yes` and `Used for tracking: No`. Mark "Designed for Kids" as **No** — Prime Kids is a tool for parents, not a kids' app.

## App Store review checklist (both apps)

Apple's review is stricter than Google's. Common rejection reasons and how to pre-empt them:

| Rejection reason | Pre-empt |
|---|---|
| "App doesn't run / crashes on launch" | Test on a real device, not just simulator |
| "Missing privacy policy URL" | Set the URL in App Store Connect *and* link it in-app under Settings |
| "Sign in with Apple required" | If you use ANY social login (Google, Facebook, etc.), Apple requires Sign in with Apple as an option. Email/password is exempt. |
| "Insufficient demo account" | In App Store Connect → Build → "App Review Information": provide review email, password, AND pairing code (PRIME888) |
| "App uses location but no clear in-app benefit shown" | First screen of the parent app should make the "see your child's location" feature visible |
| "Family Controls used outside permitted use" | Child app description must explicitly state it is for parental monitoring of a paired child, not generic device restriction |
| "Background location use not justified" | Same as Play Store — provide a video URL in App Review Information if needed |

### App Review Information (fill this for both apps)

In App Store Connect, under the version page, scroll to **App Review Information**:

```
Sign-In Required: Yes

Demo Account
  Username: review@parenthelper.com
  Password: ReviewTest2026!

Notes:
  - Parent app: sign in with the credentials above. The account has two
    seeded children (Saraa, age 9; Bat, age 13) with sample data.
  - Child app: enter pairing code PRIME888 to pair with the seeded review
    account. No real family data is exposed.
  - The Android version of both apps is published on Google Play
    (com.parenthelper.parent, com.parenthelper.child) for context.
```

### Apple-specific gotchas

1. **Marketing claims**: don't say "we will track everywhere your child goes" — Apple flags this as creepy framing. Use "see your child's location" instead.
2. **Screenshots with real names/photos**: blur any real PII; Apple has been known to reject screenshots that look like real users.
3. **Web view content**: if the parent app uses any WebView (it shouldn't), the content shown in it must also comply with App Store guidelines.
4. **Subscriptions**: if you add paid subscriptions later, you MUST use Apple's in-app purchase — no Stripe, no PayPal. Apple takes 15–30%.

## Troubleshooting

### "EAS build failed: Apple ID requires 2FA"
Generate an app-specific password at https://appleid.apple.com/account/manage → "App-Specific Passwords". Use that instead of your real password when EAS prompts.

### "Profile doesn't include the entitlement"
If Family Controls entitlement isn't applied, your provisioning profile won't include it. Re-generate the profile in https://developer.apple.com/account/resources/profiles/list after the entitlement is approved, then re-download in Xcode.

### "App Sandbox: write attempt failed"
iOS extensions can only write to the App Group's shared container, not their own sandbox. Use `FileManager.default.containerURL(forSecurityApplicationGroupIdentifier: "group.com.parenthelper.child")` not standard `URLs.documentDirectory`.

### "Family Controls authorization denied on simulator"
Family Controls requires a real device. Use an iPhone, not the simulator.

### "Push notifications work in Sandbox but not Production"
APNs has separate dev/prod environments. EAS production builds target production APNs. Ensure your Firebase APNs key is uploaded *without* selecting "Sandbox only".
